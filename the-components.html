    3. The Components

    So far, each example has fit into a single component, [App.vue]. A real application contains dozens of them: a navigation bar, forms, windows... Each component is a self-contained piece of the interface (its HTML, its code, its style) and is reusable. This chapter shows how components fit together and communicate.

    <!--
  =========================================================================
  07-composants/src/components/CarteMedecin.vue - un composant ENFANT
  -------------------------------------------------------------------------
  Il reçoit ses données de son parent par des PROPS (propriétés), déclarées
  avec defineProps. Le type TypeScript des props est vérifié à la
  compilation : <CarteMedecin :medecin="42"> serait refusé.

  Règle d'or : un composant ne MODIFIE JAMAIS ses props. Les données
  descendent du parent vers l'enfant ("one-way data flow") ; pour
  demander un changement, l'enfant émet un événement (cf. exemple 08).
  =========================================================================

<script setup lang="ts">
import { computed } from 'vue';
import type { Medecin } from '../medecin';

// withDefaults: a default value for optional props (?)
const props = withDefaults(
  defineProps<{
    medecin: Medecin;
    rang: number;
    compact?: boolean;
  }>(),
  { compact: false },
);

// A computed property based on a prop: recalculated if the parent changes the prop
const initiales = computed(() => `${props.medecin.prenom[0]}${props.medecin.nom[0]}`);
</script>

<template>
  <div class="card h-100" :class="{ 'border-success': medecin.disponible }">
    <div class="card-body d-flex gap-3 align-items-center">
      <div class="initiales">{{ initiales }}</div>
      <div>
         <!-- In the template, props are used directly by name -->
        <h2 class="h6 mb-1">{{ rang }}. {{ medecin.titre }} {{ medecin.prenom }} {{ medecin.nom }}</h2>
        <p v-if="!compact" class="mb-0 text-muted small">{{ medecin.specialite }}</p>
      </div>
    </div>
  </div>
</template>

<style scoped>
.initiales {
  width: 2.5rem;
  height: 2.5rem;
  border-radius: 50%;
  display: flex;
  align-items: center;
  justify-content: center;
  background: #0d6efd;
  color: white;
  font-weight: bold;
}
</style>
    • Line 16: [import type] imports only one type: nothing from this import remains in the resulting [JavaScript];
    • Lines 19–26: [defineProps<{...}>()] declares the component’s props—that is, the data it receives from its parent—along with their types. A prop followed by [?] is optional; [withDefaults] gives it a default value. [defineProps] does not need to be imported: it is a “macro” recognized by the [.vue] file compiler;
    • Line 29: In the script, the props are read via the [props] object. [computed] tracks the props: if the parent changes the assigned doctor, the initials are recalculated;
    • line 38: In the template, props are used directly by name;
    • line 39: a prop can modify the display.

import { ref } from 'vue';
// In <script setup>, an imported component is immediately available in the template
import CarteMedecin from './components/CarteMedecin.vue';
import type { Medecin } from './medecin';

const medecins = ref<Medecin[]>([
  { id: 1, titre: 'Mme', prenom: 'Marie', nom: 'PELISSIER', specialite: 'généraliste', disponible: true },
  { id: 2, titre: 'Mr', prenom: 'Paul', nom: 'TATOU', specialite: 'pédiatre', disponible: false },
  { id: 3, titre: 'Melle', prenom: 'Sophie', nom: 'DUPONT', specialite: 'généraliste', disponible: true },
]);
const compact = ref(false);

// the parent modifies SES data: the affected children are updated
function inverserDisponibilite(): void {
  for (const m of medecins.value) {
    m.disponible = !m.disponible;
  }
}
</script>

<template>
  <div class="container py-4">
    <h1 class="h3 mb-3">Exemple 07 - les composants et leurs props</h1>
    <div class="d-flex gap-3 mb-3">
      <label class="form-check-label"><input v-model="compact" type="checkbox" class="form-check-input"> affichage compact</label>
      <button class="btn btn-sm btn-outline-primary" @click="inverserDisponibilite">Inverser les disponibilités</button>
    </div>
    <div class="row g-3">
      <div v-for="(m, i) in medecins" :key="m.id" class="col-md-4">
         <!-- :medecin="m" passes the OBJET m (an expression);
             compact, sans deux-points, transmettrait la CHAÎNE "compact" -->
        <CarteMedecin :medecin="m" :rang="i + 1" :compact="compact" />
      </div>
    </div>
  </div>
</template>
    • line 14: in [<script setup>], an imported component is immediately usable in the template, like a new tag;
    • line 43: Each card receives the doctor SON. [:medecin="m"] (with a colon) passes the value of the expression [m]; without the colon, the character string ["m"] would be passed, which [TypeScript] would reject here. Component tag names are written as [PascalCase] to distinguish them from HTML tags;
    • lines 25–29: the parent modifies SES data; the affected maps update.

    The golden rule: a component never modifies its own props. Data flows from the parent to the child ([one-way data flow]): the parent owns it. To request a change, the child emits an event, which the parent processes: this is the subject of the following example.

    <!--
  =========================================================================
  08-evenements-composants/src/components/Compteur.vue
  -------------------------------------------------------------------------
  Un enfant qui PRÉVIENT son parent : defineEmits déclare les événements
  qu'il peut émettre, avec le type de leurs données. Le parent les écoute
  comme des événements HTML : <Compteur @change="..." @limite="...">.
  =========================================================================
-->
<script setup lang="ts">
import { ref } from 'vue';

const props = defineProps<{ libelle: string; max: number }>();

// two events: 'change' (with the new value) and 'limit' (without data)
const emit = defineEmits<{
  change: [valeur: number];
  limite: [];
}>();

const valeur = ref(0);

function plus(): void {
  if (valeur.value >= props.max) {
    emit('limite');
    return;
  }
  valeur.value++;
  emit('change', valeur.value);
}
</script>

<template>
  <div class="d-flex align-items-center gap-2 mb-2">
    <span class="w-25">{{ libelle }}</span>
    <button class="btn btn-sm btn-outline-primary" @click="plus">+1</button>
    <span class="badge text-bg-secondary">{{ valeur }} / {{ max }}</span>
  </div>
</template>
    • Lines 16–19: [defineEmits] declares the events that the component can trigger, along with their data types: [change] carries a number, [limite] carries nothing;
    • Lines 25 and 29: Emitting an event. [TypeScript] verifies the event name and its data type;
    • Line 21: The child is allowed to have its own state: [valeur] belongs to it, not to the parent.

    <!--
  =========================================================================
  08-evenements-composants/src/components/ChampTexte.vue
  -------------------------------------------------------------------------
  Un champ de formulaire "maison" (libellé + champ + aide + compteur de
  caractères) qui accepte v-model, comme un <input> ordinaire :
      <ChampTexte v-model="nom" libelle="Nom" :max="20" />

  defineModel() crée une ref reliée au v-model du parent : la LIRE donne la
  valeur du parent, l'ÉCRIRE émet l'événement 'update:modelValue', que le
  parent traite en mettant à jour sa donnée. Les données restent donc bien
  la propriété du parent.
  =========================================================================
-->
<script setup lang="ts">
import { useId } from 'vue';

const modele = defineModel<string>({ required: true });
defineProps<{ libelle: string; max: number; aide?: string }>();

// a unique identifier per instance, to link <label for> and <input id>
const id = useId();
</script>

<template>
  <div class="mb-3">
    <label class="form-label" :for="id">{{ libelle }}</label>
     <!-- v-model="model": the native field is linked to the ref of defineModel -->
    <input :id="id" v-model="modele" class="form-control" :maxlength="max" :class="{ 'is-invalid': modele.length === max }">
    <div class="form-text">{{ aide }} ({{ modele.length }} / {{ max }})</div>
  </div>
</template>
    • Line 18: [defineModel] creates a [ref] linked to the parent’s [v-model]. Reading it returns the parent’s value; writing to it triggers the [update:modelValue] event, which the parent handles by modifying the given SA. [v-model="nom"] on a component is simply a shortcut for the [modelValue] property and this event: the data remains the property of the parent;
    • line 22: [useId()] provides a unique identifier per component instance: the two [ChampTexte] instances on the page will not have the same [id], and each [<label for>] correctly refers to the SON field;
    • Line 29: The native field is linked to the [ref] from [defineModel].

  =========================================================================
  08-evenements-composants/src/App.vue - le parent écoute ses enfants
  -------------------------------------------------------------------------
  Deux façons pour un enfant de faire remonter une information :
    1. émettre un événement, que le parent écoute avec @ (Compteur) ;
    2. v-model sur un composant (ChampTexte) : un raccourci pour la prop
       modelValue + l'événement update:modelValue.

<script setup lang="ts">
import { computed, ref } from 'vue';
import Compteur from './components/Compteur.vue';
import ChampTexte from './components/ChampTexte.vue';

const total = ref(0);
const message = ref('');
const prenom = ref('Marie');
const nom = ref('PELISSIER');
const nomComplet = computed(() => `${prenom.value} ${nom.value.toUpperCase()}`);

// the 'change' event handler: it receives the data sent
function surChange(libelle: string, valeur: number): void {
  total.value++;
  message.value = `${libelle} vaut maintenant ${valeur}`;
}
</script>

<template>
  <div class="container py-4" style="max-width: 640px">
    <h1 class="h3 mb-3">Exemple 08 - événements et v-model sur un composant</h1>

    <div class="card p-3 mb-4">
      <h2 class="h6">1. Des événements émis par les enfants</h2>
      <Compteur libelle="Cafés" :max="3" @change="(v) => surChange('Cafés', v)" @limite="message = 'Pas plus de 3 cafés !'" />
      <Compteur libelle="Verres d'eau" :max="8" @change="(v) => surChange(`Verres d'eau`, v)" @limite="message = 'Assez bu.'" />
      <p class="mb-0">Total des clics : {{ total }} - <em>{{ message }}</em></p>
    </div>

    <div class="card p-3">
      <h2 class="h6">2. v-model sur un composant</h2>
      <ChampTexte v-model="prenom" libelle="Prénom" :max="20" aide="Obligatoire" />
      <ChampTexte v-model="nom" libelle="Nom" :max="20" aide="Mis en majuscules à l'affichage" />
      <p class="mb-0">Données du parent : <strong>{{ nomComplet }}</strong></p>
      <button class="btn btn-sm btn-outline-secondary mt-2 align-self-start" @click="prenom = ''; nom = ''">Vider (depuis le parent)</button>
    </div>
  </div>
</template>
    • Line 35: The parent listens for events from its children using [@], just like HTML events. The arrowed function [(v) => surChange('Cafés', v)] receives the event data; [@limite] executes a single instruction;
    • line 42: [v-model] on a component;
    • line 45: when PARENT empties its data, the fields follow: the link works both ways.

    <!--
  =========================================================================
  09-slots/src/components/Carte.vue - un GABARIT réutilisable
  -------------------------------------------------------------------------
  Les props transmettent des DONNÉES ; les slots transmettent du CONTENU
  (du HTML, d'autres composants). Carte fixe le cadre (bordure, en-tête,
  pied), le parent fournit ce qu'il y a dedans :
    - <slot />              le slot par défaut : le contenu "principal" ;
    - <slot name="entete">  un slot nommé, rempli par <template #header> ;
    - le texte placé ENTRE <slot> et </slot> est affiché si le parent ne
      fournit rien (contenu par défaut).
  C'est l'équivalent, côté client, du gabarit layout.hbs et de son {{{body}}}
  dans le cours NestJS.
  =========================================================================
-->
<script setup lang="ts">
defineProps<{ couleur?: 'primary' | 'success' | 'danger' }>();
</script>

<template>
  <div class="card mb-3" :class="couleur ? `border-${couleur}` : ''">
    <div class="card-header" :class="couleur ? `text-bg-${couleur}` : ''">
      <slot name="entete">Sans titre</slot>
    </div>
    <div class="card-body">
      <slot />
    </div>
     <!-- $slots.footer: Did the parent provide a footer? If not, no empty <div> -->
    <div v-if="$slots.pied" class="card-footer text-muted small">
      <slot name="pied" />
    </div>
  </div>
</template>
    • line 23: a named slot; the text between [<slot>] and [</slot>] is displayed if the parent provides nothing;
    • line 26: the default slot: the “main” content;
    • line 29: [$slots] specifies which slots the parent has filled: without a footer, there is no empty [<div>].

    This is the client-side equivalent of the [layout.hbs] template and its [{{{body}}}] in the [NestJS] course.

  =========================================================================
  09-slots/src/components/Tableau.vue - un tableau GÉNÉRIQUE, à slot "scopé"
  -------------------------------------------------------------------------
  generic="T" : un composant générique, comme une classe générique
  TypeScript - il affiche des lignes de n'importe quel type T.

  Le tableau sait parcourir les lignes, mais pas comment afficher une
  ligne : il PASSE chaque ligne à son slot (<slot name="ligne" :ligne="l">),

<script setup lang="ts" generic="T extends { id: number }">

</script>

<template>

    <thead>
      <tr><th v-for="c in colonnes" :key="c">{{ c }}</th></tr>
    </thead>
    <tbody>
      <tr v-for="(l, i) in lignes" :key="l.id">
        <slot name="ligne" :ligne="l" :index="i" />
      </tr>
      <tr v-if="lignes.length === 0">
        <td :colspan="colonnes.length" class="text-muted"><slot name="vide">Aucune donnée.</slot></td>
      </tr>
    </tbody>
  </table>
</template>
    • line 15: a generic component, such as a generic class [TypeScript]: [T] is the type of the lines, for which only one property is required: [id] (for the key of [v-for]);
    • Line 26: The array knows how to iterate through the lines, but not how to display a line. It passes each line to its slot, and the parent displays it. This is referred to as a “scoped” slot: the content provided by the parent uses data that belongs to the child.

  =========================================================================
  10-cycle-de-vie/src/components/Horloge.vue
  -------------------------------------------------------------------------
  Le cycle de vie d'un composant :
    1. setup      : le code de <script setup> s'exécute (création) ;
    2. onMounted  : le composant est AFFICHÉ, ses éléments HTML existent ;
    3. onUpdated  : son affichage vient d'être mis à jour ;
    4. onUnmounted: le composant a été RETIRÉ de la page.
  Une horloge lance une minuterie (setInterval) à l'affichage... et doit
  impérativement l'arrêter quand elle disparaît : sinon la minuterie
  continuerait de tourner pour rien (fuite de mémoire).
  =========================================================================

<script setup lang="ts">
import { onMounted, onUnmounted, ref } from 'vue';

const emit = defineEmits<{ journal: [message: string] }>();

const heure = ref(new Date().toLocaleTimeString());
let minuterie: number | undefined;

emit('journal', 'Horloge : setup (création)');

// 11-composables/src/composables/useHorloge.ts - a COMPOSABLE
// -------------------------------------------------------------------------
// A composable is a simple function whose name begins with "use"
// by convention, which combines a reactive state ET with the corresponding logic
// (in this case: the timer, its start, and its stop). Any component that

//

// role previously played, on the server side, by the NestJS services.

  onUnmounted(() => window.clearInterval(minuterie));

// 12-confirmation/src/composables/useConfirmation.ts
// -------------------------------------------------------------------------
// "Are you sure?": window.confirm() exists, but we can neither
// style it or translate its buttons. We replace it with a window
// Bootstrap window (FenetreConfirmation.vue), controlled by this composable.
//
// Tip: confirm(message) returns a PROMESSE, which evaluates to true (Yes)
// or false (No) when the user responds. The calling code is written
// just as simply as with window.confirm:
//
//      if (await confirm('Delete this doctor?'')) { ... }
//
// The state (displayed message, function to call upon response) is declared
// HORS of the function: it is therefore UNIQUE for the entire application. A
// A single window, created once in App.vue, serves all components.
// =========================================================================

import { readonly, ref } from 'vue';

const message = ref<string | null>(null); // null: window closed
let repondre: ((reponse: boolean) => void) | null = null;

export function useConfirmation() {
  function confirmer(texte: string): Promise<boolean> {
    message.value = texte;
    return new Promise<boolean>((resolve) => {
      repondre = resolve;
    });
  }

  function reponse(oui: boolean): void {
    message.value = null;
    repondre?.(oui);
    repondre = null;
  }

   // readonly: components read the message; only the composable modifies it
  return { message: readonly(message), confirmer, reponse };
}

    • line 39: components can read the message, but not modify it.
