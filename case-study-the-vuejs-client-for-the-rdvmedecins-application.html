    10. Case Study: The Vue.js client for the RdvMedecins application

    10.1. The Problem

    The [RdvMedecins] application allows users to schedule appointments at a doctor’s office. The [NestJS] course wrote it as a HTML application, in which the server generated the pages. Here we are writing the client [Vue.js]: the MÊMES pages, generated in the browser from the JSON data on the server described in the chapter “The RdvMedecins Server: A Black Box.”

    The client must provide everything that the HTML application provided:

    • a login page, protected by a CAPTCHA, with the option to create a patient account;
    • a doctor’s schedule for a given day, with appointment booking (patient selection window) and cancellation;
    • for the administrator, management of doctors and clients (list, add, edit, delete);
    • for the patient, a personal dashboard (showing upcoming appointments, which they can cancel) and account management;
    • two languages: French and English;
    • unique URLs ([/agenda?idMedecin=1&jour=...]), which can be reloaded, bookmarked, and navigated using the browser’s Back/Forward buttons.

    10.2. Installation and Execution

    The JSON server must be installed and running (see previous chapter). To use the client in a browser, you do not need the CAPTCHA test mode: you can leave PAS blank in the server’s [.env] file.

    In a console window open to the [rdvmedecins-vuejs] folder:

    npm install
npm run dev

    Then open http://localhost:5173 in a browser. The demo accounts are listed on the login page (password = login).

    The [Vite] server in the examples also uses port 5173. If this port is already in use, [Vite] will take another one (5174...) and display it in the console: you must then open that address.

import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    proxy: {
       '/api': 'http://localhost:8080',
    },
  },
   // npm run preview: serves dist/ (after npm run build), using the same proxy
  preview: {
    port: 4173,
    proxy: {
       '/api': 'http://localhost:8080',
    },
  },
});
    • lines 21–23: the proxy for requests from [/api] to the server JSON;
    • lines 26–31: the same proxy for [npm run preview].

    An important detail: the application uses “clean” addresses ([/agenda], [/mon-espace]). If you reload the page [/agenda], the browser requests [/agenda] from the server for [Vite]. Since the server cannot find a file with that name, it returns [index.html] (this is its default behavior for a single-page application); the application launches, and its router displays the calendar page.

const app = createApp(App);

app.use(i18n);
app.use(router);

quandNonAuthentifie(() => {
  useSessionStore().oublier();

// a title, a first name, a last name

  titre: string;
  prenom: string;
  nom: string;
}

// a doctor or a client: GET /api/doctors, GET /api/clients/:id...

  version: number; // optimistic lock: to be sent back with a modification

// api/client-http.ts - the function that sends TOUTES requests to API
// -------------------------------------------------------------------------
// Reuse of examples from commun/api.ts, with a new feature: centralized handling
// Centralized handling of the 401 response.
//
// A 401 can occur at any time: the token has expired (2 hours), the
// account has been deleted, the server has restarted with a different
// secret key... Rather than handling this case in each component, we
// notify the UNE function, registered at startup (see main.ts), which forgets
// the user and redirects to the login page.
// =========================================================================

export class ErreurApi extends Error {
  constructor(
    public readonly statusCode: number, // 0: the server did not respond
    public readonly cle: string, // translation key: 'ERRORS.LOGIN_TAKEN'
    public readonly params: Record<string, string> = {},
    public readonly champs: Record<string, string> = {}, // error in each field
  ) {
    super(cle);
    this.name = 'ErreurApi';
  }
}

// The function called for every 401 response (see main.ts)
let surNonAuthentifie: (erreur: ErreurApi) => void = () => {};

export function quandNonAuthentifie(fonction: (erreur: ErreurApi) => void): void {
  surNonAuthentifie = fonction;
}

type Methode = 'GET' | 'POST' | 'PUT' | 'DELETE';

export interface OptionsRequete {
   // public routes (login, CAPTCHA, etc.) and GET /api/auth/moi
   // handle the 401 responses themselves: no automatic redirection
  ignorer401?: boolean;
}

export async function requete<T>(methode: Methode, url: string, corps?: unknown, options: OptionsRequete = {}): Promise<T> {
  let reponse: Response;
  try {
    reponse = await fetch(`/api${url}`, {
      method: methode,
      headers: corps !== undefined ? { 'Content-Type': 'application/json', Accept: 'application/json' } : { Accept: 'application/json' },
      body: corps !== undefined ? JSON.stringify(corps) : undefined,
    });
  } catch {
    throw new ErreurApi(0, 'ERRORS.SERVER_UNREACHABLE');
  }

   // read as text and then converted: an empty response, or one that is not
   // JSON (server down: the Vite proxy responds), does not
   // cause the application to crash
  const texte = await reponse.text();
  let donnees: unknown = null;
  try {
    donnees = texte ? JSON.parse(texte) : null;
  } catch {
    donnees = null;
  }

  if (reponse.ok) {
    return donnees as T;
  }

  const e = (donnees ?? {}) as { cle?: string; params?: Record<string, string>; champs?: Record<string, string> };
  const erreur = new ErreurApi(
    reponse.status,
     // no key: it wasn’t our server that responded, but a proxy
     // (Vite: 500 with no body; nginx: 502, 504...)
    e.cle ?? (reponse.status >= 500 ? 'ERRORS.SERVER_UNREACHABLE' : 'ERRORS.SERVER_ERROR'),
    e.params,
    e.champs,
  );
  if (reponse.status === 401 && !options.ignorer401) {
    surNonAuthentifie(erreur);
  }
  throw erreur;
}

// stores/session.ts - Is QUI logged in?
// -------------------------------------------------------------------------
// The Pinia store for the session: the logged-in user (or null), and
// is what we infer from this (is it ADMIN? a patient?).
//
// The token JWT itself is not PAS here: it is in a cookie httpOnly that
// is handled only by the browser. The store keeps only the DESCRIPTION from
// the user, returned by the server ({ login, name, role }).
//
// At startup (and after a F5), the store is empty: `verifier()` sends a
// the server, just once, to determine who is connected (GET /api/auth/moi).
// =========================================================================

import { computed, ref } from 'vue';
import { defineStore } from 'pinia';
import { rdvApi } from '../api/rdvmedecins.api';
import type { Role, Utilisateur } from '../api/types';

export const useSessionStore = defineStore('session', () => {
  const utilisateur = ref<Utilisateur | null>(null);
   // Has the question “Who is logged in?” already been asked of the server?
  let verification: Promise<void> | null = null;

  const connecte = computed(() => utilisateur.value !== null);
  const role = computed<Role | null>(() => utilisateur.value?.role ?? null);
  const estAdmin = computed(() => role.value === 'ADMIN');
  const estPatient = computed(() => role.value === 'USER');
   // ADMIN and DOCTOR: schedule and cancel appointments for any patient
  const estGestionnaire = computed(() => role.value === 'ADMIN' || role.value === 'DOCTOR');

   // The home page for each role, immediately after logging in
  const pageAccueil = computed(() => (estPatient.value ? '/mon-espace' : '/agenda'));

   // called by the router guard before CHAQUE navigation; does not query
   // the server only the first time (the connection is maintained and reused)
  function verifier(): Promise<void> {
    verification ??= rdvApi
      .moi()
      .then((u) => {
        utilisateur.value = u;
      })
      .catch(() => {
        utilisateur.value = null; // 401: Unauthorized; or server unreachable
      });
    return verification;
  }

  async function connecter(login: string, password: string, captchaId: string, captcha: string): Promise<void> {
    utilisateur.value = await rdvApi.connecter(login, password, captchaId, captcha);
  }

   // the user has changed their name or login (PUT /api/my-account)
  function mettreAJour(u: Utilisateur): void {
    utilisateur.value = u;
  }

  async function deconnecter(): Promise<void> {
    try {
      await rdvApi.deconnecter();
    } finally {
      oublier();
    }
  }

   // without making a request to the server: session expired, account deleted
  function oublier(): void {
    utilisateur.value = null;
  }

  return {
    utilisateur,
    connecte,
    role,
    estAdmin,
    estPatient,
    estGestionnaire,
    pageAccueil,
    verifier,
    connecter,
    mettreAJour,
    deconnecter,
    oublier,
  };
});
    • Line 21: the logged-in user, as described by the server. The token itself isn’t there—it’s in a cookie that only the browser handles;
    • lines 25–30: what is inferred from this, used by the pages and the navigation bar;
    • line 33: the home page for each role: “My Space” for a patient, the calendar for others;
    • lines 37–47: the question “Who is logged in?”, asked of the server only PREMIÈRE times. The promise is kept in [verification]: subsequent calls reuse it (the operator [??=] only assigns a value if the variable is [null] or [undefined]). It cannot fail: an error (401, server unreachable) means “no one”;
    • lines 49–51: the login. If it fails, [rdvApi.connecter] rejects its promise with a [ErreurApi], which passes through this function to the login page;
    • line 54: After making changes to their account, the patient may have changed their name;
    • lines 58–64: [finally]: the user is forgotten, even if the server did not respond;
    • line 67: without making any request to the server (session expired, account deleted).

    // =========================================================================
// stores/messages.ts - messages displayed to the user
// -------------------------------------------------------------------------
// Same layout as the HTML application:
//    - a SUCCÈS is displayed as HAUT on the page (green banner);
//    - a ERREUR appears as BAS, on a light pink background (the “sticky” area).
// A message is a translation CLÉ (plus its settings): it is therefore re-translated
// on its own if the user changes the language.
//
// "Flash" messages: an action that ends with a page change
// page (booking, adding a doctor, etc.) places its message using flash();
// it will be displayed on the page SUIVANTE, then disappear upon navigation
// (see router.afterEach in router.ts). On the server side, this was the
// role of the short-lived cookie "rdvmedecins_flash".
// =========================================================================

import { ref } from 'vue';
import { defineStore } from 'pinia';
import { ErreurApi } from '../api/client-http';

export interface Message {
  cle: string;
  params?: Record<string, string>;
}

export const useMessagesStore = defineStore('messages', () => {
  const succes = ref<Message | null>(null);
  const erreur = ref<Message | null>(null);
   // the messages to be displayed on the next page
  let enAttente: { succes: Message | null; erreur: Message | null } | null = null;

  function afficherSucces(cle: string, params?: Record<string, string>): void {
    succes.value = { cle, params };
    erreur.value = null;
  }

  function afficherErreur(cle: string, params?: Record<string, string>): void {
    erreur.value = { cle, params };
    succes.value = null;
  }

   // a ErreurApi -> the page message; any other error is a
   // client-side issue, which is logged (browser console)
  function afficherErreurApi(e: unknown): void {
    if (!(e instanceof ErreurApi)) {
      throw e;
    }
    afficherErreur(e.cle, e.params);
  }

  function effacer(): void {
    succes.value = null;
    erreur.value = null;
  }

   // for the page SUIVANTE
  function flash(type: 'succes' | 'erreur', cle: string, params?: Record<string, string>): void {
    enAttente ??= { succes: null, erreur: null };
    enAttente[type] = { cle, params };
  }

   // called after each page view (router.afterEach)
  function nouvellePage(): void {
    succes.value = enAttente?.succes ?? null;
    erreur.value = enAttente?.erreur ?? null;
    enAttente = null;
  }

  return { succes, erreur, afficherSucces, afficherErreur, afficherErreurApi, effacer, flash, nouvellePage };
});
    • lines 21–24: A message consists of a translation CLÉ and its parameters. It therefore automatically translates itself if the user changes languages;
    • lines 27–28: the success message (displayed at the top) and the error message (at the bottom) for the current page;
    • lines 44–49: a [ErreurApi] becomes the page’s message. Any other error is a CLIENT anomaly (a programming error): it is allowed to be logged and will be displayed in the browser console;
    • lines 57–60: a message for the SUIVANTE page. An action that results in a page change (booking, adding a doctor, logging in after creating an account) displays this message before navigating to the next page;
    • lines 63–67: called after each page navigation (see [router.ts]): messages from the previous page disappear, and pending messages appear. In the HTML application, this was the role of the short-lived cookie [rdvmedecins_flash].

export function aujourdhui(): string {

// true if [jour] is a valid date in the yyyy-MM-dd format
export function estUneDateValide(jour: unknown): jour is string {
  if (typeof jour !== 'string' || !/^\d{4}-\d{2}-\d{2}$/.test(jour)) {
    return false;
  }
  const date = new Date(`${jour}T00:00:00Z`);
  return !isNaN(date.getTime()) && date.toISOString().slice(0, 10) === jour;
}

   // "Monday, October 5, 2026" / "Monday 5 October 2026"

  return { libelle, heure, horaire, jourLong };

import { useMessagesStore } from '../stores/messages';

export function useFormulaire() {
  const messages = useMessagesStore();
  const erreurs = ref<Record<string, string>>({}); // field -> message key
  const params = ref<Record<string, string>>({}); // message parameters ({min}...)
  const envoiEnCours = ref(false);

  function effacerErreurs(): void {
    erreurs.value = {};
    params.value = {};
  }

   // executes the send; returns true if successful. In case of ErreurApi, the
   // errors are displayed and false is returned.
  async function envoyer(action: () => Promise<void>): Promise<boolean> {
    effacerErreurs();
    envoiEnCours.value = true;
    try {
      await action();
      return true;
    } catch (e) {
      if (e instanceof ErreurApi) {
        erreurs.value = e.champs;
        params.value = e.params;
      }
      messages.afficherErreurApi(e);
      return false;
    } finally {
      envoiEnCours.value = false;
    }
  }

  return { erreurs, params, envoiEnCours, envoyer, effacerErreurs };
}
